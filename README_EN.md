# Merchant Profit & Inventory Tool

[中文版](README.md)

This is a Phase 1 local tool: it requires no TikTok password, runs no external servers, and does not modify your live product listings.

## Available Now

1. For temporary use: Double-click `启动工具.cmd` and open `http://127.0.0.1:8765`. No changes to Windows PowerShell execution policies are required.
2. To run automatically on startup: Double-click `设置开机后台运行.cmd` once. It uses the Windows "Startup" folder; no administrator privileges are needed, and no black console window will appear. It will run in the background after you log into Windows; simply bookmark `http://127.0.0.1:8765` in your browser.
3. Upload the **Income** and **All Orders** `.xlsx` files exported from TikTok Shop.
4. The tool merges data using the `Order ID`: the `Total settlement amount` from the Income report represents net revenue, while the actual product quantity from the Orders report is used to deduct costs.
5. Enter the cost once for each TikTok platform `SKU ID` actually sold. Costs can have an effective date.
6. Items are marked "Needs Verification" (requiring review) if quantities mismatch, orders are missing, or cost data is absent; the tool will not display misleading profit figures.

A blank `Seller SKU` field does not affect the tool's operation. The primary key for costs is the platform `SKU ID` automatically generated by TikTok; product names and variants serve only as human-readable references.

## Inventory Synchronization: Current Status

Local inventory mapping and **simulated inventory deduction** have been implemented to validate calculations involving a shared inventory pool, safety buffers for individual stores, and target sellable inventory. It is not yet connected to the TikTok production environment and will never modify your actual inventory without authorization.

The following steps must be completed before writing actual inventory updates:

1. Developer onboarding on TikTok Shop Partner Center;
2. Creation of a **Custom App** for Malaysia / Local Sellers;
3. API activation, HTTPS redirect URL configuration, and OAuth authorization for each store;
4. Application for and approval of the necessary product write scopes (the inventory update API documentation lists `seller.product.write`);
5. Testing in the Sandbox environment for orders, cancellations, retries, rate limiting, and inventory reconciliation. Do not simulate Seller Centre operations using Selenium, browser scripts, cookies, or store passwords. Use only official OAuth and APIs.

## Known Limitations

- Profit is calculated as `Total settlement amount - Actual cost of non-returned items`. Do not deduct platform fees, shipping costs, or creator commissions again, as these are already included in the net settlement amount.
- For orders containing multiple items, the tool calculates profit for the **entire order only**. To break this down by individual item, an allocation rule must be selected first.
- Cost data stored locally in `data/state.json` is unencrypted; do not upload this directory to public repositories.

## Render Test Deployment

The TikTok OAuth callback URL is `https://erp-sistem.onrender.com/tiktok/callback`. After passing the Partner Center review, configure `TIKTOK_APP_KEY`, `TIKTOK_APP_SECRET`, and `TIKTOK_TOKEN_ENCRYPTION_KEY` in the Render Environment Variables; do not commit these keys to GitHub.
`TIKTOK_TOKEN_ENCRYPTION_KEY` must be a random key in Fernet format. The current implementation validates the one-time `state` parameter, exchanges the authorization code for an access token using the App Secret, and stores the encrypted token.
Render's free instances lack persistent storage, so local tokens are lost upon restart. Therefore, before connecting real stores or enabling multi-user access, you must migrate to a persistent database and a paid/persistent deployment solution.

This project can be deployed as a single-user test site. Render uses the `Dockerfile` in the root directory to automatically install Python dependencies and start the service. After creating a **Web Service** on Render:

1. Select this private repository;
2. Choose Docker as the environment;
3. Add `APP_ACCESS_PASSWORD` to the Environment variables and set it to a long, unique password;
4. After deployment, open the HTTPS URL provided by Render; the browser will prompt you for a username and password. The username is fixed as `merchant`.

Render's free instances go to sleep, and local uploads, cost records, and downloaded reports will be lost upon restart. Therefore, this setup is suitable only for verifying online operations and the TikTok OAuth technical workflow; it is not appropriate for long-term storage of tax data or for use by multiple users.
